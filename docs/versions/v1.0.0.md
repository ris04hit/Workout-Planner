# v1.0.0 — 2026-04-27

Initial release. Full working application with all core features.

---

### Added

**Workout Logging**
- Log workouts with per-exercise set tracking (no group selection required)
- Two set modes: reps (reps + weight) and time (duration_sec + weight)
- Add and remove sets dynamically per exercise
- Duplicate workout detection (same date → 409)
- Edit past workouts; update preserves original date and ID
- Delete workouts

**Exercise-Based Suggestion Algorithm** (`src/core_logic.py`)
- Flat exercise library with per-muscle contribution maps (`"QUADS": 0.8` etc.)
- `compute_fatigue_from_history()` — per-muscle fatigue replayed from full workout history with daily decay; never stored in a file
- `compute_weekly_load_from_history()` — rolling 7-day muscle load from history; never stored in a file
- `select_workout()` scores every enabled exercise against current fatigue, weekly load, soreness, recency, and priority, then greedily selects a balanced session
- Greedy loop applies four hard filters per exercise: fatigue/sore block, pattern limit, family deduplication, muscle saturation
- Fallback chain: relax structural constraints → relax soreness block → first enabled exercise

**Configuration System**
- Per-user config stored as overrides; merged over defaults in `data/default/config.json` at runtime
- Configurable: `muscle_weights`, `weekly_targets` (min/mid/max per muscle), `fatigue_decay`, `max_difficulty_allowed`, `target_exercise_count`, `pattern_limits`, `muscle_usage_limit`, `sore_block_threshold`, `fatigue_block_threshold`, `sore_penalty_factor`
- Config history: snapshots stored with timestamps
- Revert to any history entry; reset to factory defaults

**Exercise Library**
- Flat exercise list — each exercise has name, pattern, family, difficulty, priority, enabled flag, and muscle contribution map
- Add, remove, enable/disable exercises
- `data/default/exercises.json` committed as seed data; user overrides stored per-user
- Exercises filtered by `max_difficulty_allowed`; disabled exercises excluded from suggestions

**Soreness Tracking**
- Toggle soreness per individual muscle (`QUADS`, `CHEST`, etc.)
- Sore muscles apply `sore_penalty_factor` to exercise scores; heavy contributors can be hard-blocked via `sore_block_threshold`

**Analytics & Progress**
- Per-exercise progress: last session and all-time best (by volume)
- Volume: `sum(reps × weight)` for reps mode; `sum(duration_sec)` for time mode
- Analytics dashboard with timeframe selector (7d / 30d / 90d / all)
- Export analytics as JSON or CSV

**Export / Import**
- Export full workout history as JSON or CSV
- Import from JSON (duplicate dates skipped)

**Multi-User Support**
- Isolated data directory per user (`data/users/<username>/`)
- Forced user-creation modal on first launch
- User switcher in UI; active user persisted in `localStorage`
- `?user=<username>` query param on all API calls
- Create user with optional copy from `default`; delete user and all data

**API**
- `GET/POST /api/workout`, `PUT/DELETE /api/workout/<id>` — workout CRUD
- `GET /api/history` — alias for `GET /api/workout`
- `GET /api/suggest` — run suggestion algorithm; returns exercises + fatigue + scores
- `GET /api/fatigue` — computed fatigue + weekly load only
- `GET/POST /api/exercises`, `PUT/DELETE /api/exercises/<name>` — exercise library CRUD
- `GET/POST /api/soreness` — per-muscle soreness
- `GET/POST /api/config`, `POST /api/config/reset`, `GET /api/config/history`, `POST /api/config/revert`
- `GET /api/progress/<exercise_name>` — last session + personal best for one exercise
- `GET/POST /api/users`, `DELETE /api/users/<username>`, `GET/POST /api/current-user`

**Infrastructure**
- Flask server, vanilla ES modules frontend — no build step
- Flat JSON file storage — no database
- `conftest.py` at project root: centralised `sys.path` for all tests
- `scripts/setup.sh`: idempotent environment setup (Python venv, npm install, runtime data files)
- `scripts/run.sh`: activate venv and start Flask
- `scripts/init_default_data.py`: creates gitignored runtime files on fresh checkout

**Tests**
- Python unit tests across all storage modules, API endpoints, and core logic
- JavaScript Jest tests for sets, config, state, and API modules
- Test structure mirrors source: `tests/src/api/`, `tests/src/storage/`, `tests/static/js/`
